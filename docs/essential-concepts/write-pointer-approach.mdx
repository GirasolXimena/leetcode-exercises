# The Write-Pointer Approach

## The idea

A write pointer is an index that marks where the next accepted value should be written. A separate read position, often provided by a `for...of` loop or another index, examines each input value.

This is useful when an array must be compacted, filtered, or rearranged while preserving the order of the values that remain. Instead of removing an item and shifting the rest of the array, the algorithm writes the next useful value into the next available position.

```ts
let write = 0;

for (const value of values) {
  if (keep(value)) {
    values[write] = value;
    write++;
  }
}
```

The invariant is simple: before each new value is read, positions before `write` contain exactly the accepted values seen so far, in their original order.

## Example: moving zeroes

Suppose the input is `[0, 1, 0, 3, 12]` and the rule is to keep non-zero values at the front.

| Read value | Accepted prefix | `write` |
| --- | --- | ---: |
| `0` | `[]` | `0` |
| `1` | `[1]` | `1` |
| `0` | `[1]` | `1` |
| `3` | `[1, 3]` | `2` |
| `12` | `[1, 3, 12]` | `3` |

After the scan, the remaining positions are filled with zeroes, producing `[1, 3, 12, 0, 0]`.

The important detail is that the algorithm does not remove the zeroes while scanning. It only overwrites positions that have already been processed and then fills the suffix. That preserves the order of non-zero values and keeps the array length unchanged.

## Why this can be faster than removal

Operations such as `splice` can move every element after the removed position. A single middle removal can therefore cost $O(n)$. Repeating removal for many values can lead to $O(n^2)$ work.

A write-pointer scan reads each value once and writes each accepted value once. The final fill also visits each remaining position once, so the total time is $O(n)$. Because the algorithm uses only indexes and temporary values, its additional space is $O(1)$.

See the [Move Zeroes](../array/move-zeroes) exercise for the implementation and tests.

## When to use it

Consider a write pointer when:

- the output can be stored in the original array;
- the order of accepted values must be preserved;
- values can be classified as keep or discard;
- you want linear work without allocating a second full array.

The same pattern appears in removing duplicates from a sorted array, partitioning values, and filtering invalid entries in place.

## Common mistakes

- Incrementing `write` for discarded values, which leaves gaps in the accepted prefix.
- Reading from a position after it has been overwritten instead of keeping read and write roles separate.
- Forgetting to fill or remove the unused suffix when the function's contract requires a complete final array.
- Describing an algorithm as in place while silently creating another full-size array.
- Testing only the returned value and forgetting to assert the final mutated input array.

The write pointer is not a special data structure. It is a small piece of state that makes the relationship between the read position, the accepted prefix, and the final output explicit.
